# Wheelhouse User Stories

## User Stories

*Note* 

The story that is deliberately too big was split into: US-04, US-05 and US-06.

"As a mechanic, I want to assess a bike, determine the required work and cost, and know whether the customer has approved the repair, so that I can decide what work should be performed."

### US-01 Bike registration

As a counter staff member, I want to register a bike and link it to a customer, so that I may identify which bike belongs to which customer.

**Acceptance criteria**
- A bike can be registered with a customer.
- The registered bike shows the customer associated with it.
- The registered customer shows the bike associated with them.


### US-02 Bike identification

As a counter staff member, I want to be able to write the specifications of any given bike, including a serial number, so that we can correctly identify any bike even if there are two very similar bikes.


### US-03 Bike photos

As a counter staff member, I want to be able to record photos of a bike on arrival, so that there is no ambiguity on any previous damage.


### US-04 Bike problem description

As a mechanic, I want to write a description of the problem or a list, so that it is easily read by a person


### US-05 Repairs needed

As a mechanic, I would like to specify which repairs are needed and their price, so that the total cost is available.


### US-06 Bike status: workable

As a mechanic, I want to know whether a repair has been approved by the customer, so that I know whether work may begin.

**Acceptance criteria**
- The mechanic can clearly distinguish a repair that is approved for work from one that is not.
- The repair shows whether customer approval has been received.
- A repair that has been declined is displayed as not approved for work.


### US-07 Bike promise day

As an owner, I want to see which repairs have passed their promised completion date, so that I can act on delays before customers complain.


### US-08 Bike status: finished

As a counter staff member, I want to be able to check on the status of a bike seamlessly, so that I can tell a customer if it's finished when they call to ask.

**Acceptance criteria**
- The current repair status is displayed.
- The bike associated with the repair is clearly identified.
- The screen clearly indicates whether the bike is ready for pickup.


### US-09 — Completed repair pickup

As a counter staff member, I want to record when a repaired bike is picked up, so that the shop knows the bike has been returned to the customer.


### US-10 — Declined repair pickup

As a counter staff member, I want to record when a customer declines a proposed repair and picks up their bike, so that the shop knows the repair was not performed and the bike has been returned.


### US-11 Bike history

As a counter staff member, I want to have a clear history of repairs on any given bike, so that I can see what work has been done on it previously.

**Acceptance criteria**
- If there is no record of repairs on a bike, the page must say so. Not a blank screen.
- Each previous repair describes the work done.
- The selected bike displays its previous repairs.


### US-12 Flexible pricing

As an owner, I want to update the service price list without changing the prices of previous repairs, so that past charges remain accurate when the price list changes.


### US-13 Walllist prices

As a customer, I want the service prices to be readily available on the website, so that I don't have to call the shop to know them.
